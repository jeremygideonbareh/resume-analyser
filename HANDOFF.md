# HANDOFF — careerBoT

Privacy-first ATS resume analyser + student placement assistant. Vite + React 19 + TypeScript + Tailwind v4 + shadcn/ui + `motion` (framer-motion successor) + recharts + Vitest. Branches: `feat/resume-analyser` (analyser waves) and `feat/placement-assistant` (placement wave, current — never commit to main without user consent).

## What it is

A single-page app: upload/paste a resume → rule-based ATS score (category breakdown, sections detected, skills extracted, feedback) → printable report. Optional env-gated LLM feedback tier (`VITE_ENABLE_LLM`, default off — key lives server-side in `api/analyze.ts`, never in the client). **Placement Assistant**: profile management, AI chat, grammar checker, placement dashboard, mock interview practice, aptitude practice — all behind Supabase Auth.

**Brand name: careerBoT** (chosen in Todo 1.2). Signature motif: lab-dots grid + scanline (`src/index.css`), emerald accent on ink-on-paper.

## Architecture

- **Zero-upload, client-side only.** Parsing (pdfjs-dist / mammoth / TXT), analysis (rule-based), and report rendering all happen in the browser. No server, no cookies. Signed-in analyses are saved to the account (metrics + filename only — never resume text; RLS on `resume_analyses`); guests store nothing. LLM tier is an optional env-gated hook — key never in client.
- **Design identity:** ink-on-paper light theme. Tokens in `src/index.css` `:root`: paper `oklch(0.985 0 0)`, surface `oklch(0.96 0 0)`, ink `oklch(0.16 0 0)`, muted `oklch(0.45 0 0)`, accent emerald `#059669` (~`oklch(0.58 0.13 162)`). Fonts via @fontsource: Fraunces (display), Inter (body), IBM Plex Mono (data/keywords), Montserrat (800/900 — used ONLY for the hero's decorative layered words RESUME/ANALYSE/LAB via the `--font-montserrat` token → `font-montserrat` utility; the app-wide `--font-display`/Fraunces is untouched).
- **Page composition** (`src/App.tsx`): Header → Hero → ToolSection (#tool) → HowItWorks → SampleReport (#sample) → Footer.
- **Hero = interwoven depth layout** (2026-08-28, replaced the earlier Aalto 260vh scroll-expand): src/components/sections/Hero.tsx sits in a `h-[170vh]` section with a `sticky top-0 h-screen` inner layer. A shared `relative mx-auto w-[min(74vw,52rem)]` wrapper holds the centered Cloudinary video (video1_horxtt.mp4) plus all three layered words, so the words stay locked to the image corners at any viewport width. Z-ladder (under sticky Header `z-50`): `-z-10` backdrops → `z-5` RESUME (top-left) + LAB (bottom-right) behind → `z-10` video card → `z-20` ANALYSE (front, right side) → `z-30` badge (left-center) + bottom-right CTA. Decorative words are **Montserrat Black 900** with `tracking-[-0.05em]` (fresh counterweight to the Fraunces brand voice). Scroll-driven via motion/react useScroll+useSpring (NO gsap - repo convention): video scales 0.86→1 with radius shrink over p[0,0.6], words fade out + drift up over p[0,0.7]. prefers-reduced-motion → static single-screen hero without the pin/scrub.
- **Motion primitives** (`src/components/motion/`): `SectionReveal`/`StaggeredReveal` (useInView reveals), `MagneticButton` (cursor spring). All respect `prefers-reduced-motion`.
- **State machine** (`ToolSection`): `idle → parsed → analyzing → done`; every transition has a kinetic treatment (`AnalyzingSkeleton` count-up, minimum 700 ms). Parsing happens in `UploadZone` (`idle → parsing → error → success`).

## Scoring model (`src/lib/analysis.ts`)

Weighted categories (normalized from 2026 industry research):

| Category | Weight | Notes |
|---|---|---|
| Keyword match | 45 | JD keywords vs. resume tokens (headings + bullets weighted higher); without a JD, falls back to industry-standard keyword heuristics |
| Structure | 17 | Detected standard sections (summary/experience/education/skills/…), heading clarity |
| Formatting | 12 | Single-column layout, bullet usage, quantified achievements, no tables/images |
| Recency | 13 | Year presence in experience, gaps |
| Contact info | 8 | Email / phone / LinkedIn |
| Parse confidence | 5 | Plain text vs. OCR-quality/scanned content |

Score bands (from `scoreBand()` in `src/lib/report-format.ts`): `>=70` Strong · `>=40` Needs work · `<40` Weak. Report marks when a resume passes the "70% recruiter filter line".

**How to swap the lexicon:** detected skills live in `src/lib/skills-lexicon.ts` (200+ entries) — add/remove entries there; `analysis.ts` reads it for skill detection and feedback. Section heading synonyms live in `HEADING_RE`/`SECTION_NAMES` at the top of `analysis.ts`.

## Known limitations

- **Scanned/image PDFs** are detected and warned about (`possible-scanned` warning) — OCR is intentionally out of scope (Scope OUT: no OCR).
- **English-only scoring lexicon** — the skills lexicon and section-heading regex are English.
- **PDFs parse best with embedded text**; pdfjs is lazy-loaded so the first PDF takes a beat (~1 MB chunk, gzip 146 KB) — subsequent analyses are instant.
- Focus drops to `<body>` after phase transitions (parsed → analyzing → done); the next Tab re-enters the flow. Acceptable per plan scope (documented in `.omo/evidence/5-2-a11y.log`).

## Supabase Auth (Wave 2 — email + password)

- **Client wiring** (`src/lib/supabase.ts`): `getSupabase()` module-singleton `createClient(import.meta.env.VITE_SUPABASE_URL!, VITE_SUPABASE_ANON_KEY!)`; throws a clear error naming both vars when `.env.local` is missing. All auth calls live in `src/lib/auth-flow.ts` (`signUpWithEmail`/`signInWithPassword`/`sendPasswordResetEmail`/`updatePasswordFromRecovery`) — components never touch `supabase.auth.*` directly (grep-verified).
- **Password-reset redirect (FIXED 2026-08-19, live-verified)**: `sendPasswordResetEmail` passes `options.redirectTo = window.location.origin + window.location.pathname`. Without it, supabase-js defaults to `window.location.origin` alone — on GitHub Pages that is the github.io ROOT (404 "Site not found") instead of `/resume-analyser/` (confirmed live, then fixed; regression test in `auth-flow.test.ts` stubs the deployed origin/pathname). Supabase `uri_allow_list` must contain the full app URL (both slash variants are configured).
- **Session** (`src/lib/session.ts`): `useAuthSession()` wraps `supabase.auth.onAuthStateChange` → `{ session, user, signOut }`; `maskIdentifier` (email → `j***@example.com`). Persisted via Supabase's default token storage (localStorage) — reloads restore the session (real-auth behavior, distinct from the old demo). When env vars are missing the hook degrades to signed-out without crashing.
- **Sign-up flow**: `mailer_autoconfirm: true` on the Supabase project — `signUpWithEmail` returns a session immediately (no email confirmation step). Verified live 2026-08-19 (throwaway sign-up → immediate sign-in).
- **Provisioning (Todo 2.1, DONE 2026-08-19)**: project provisioned via the Management API (PowerShell `Invoke-RestMethod`, no CLI); `service_role` key + DB password live ONLY in `.env.local` (gitignored, `git check-ignore` verified); PAT rotated after setup.
- **Deploy note (LIVE 2026-08-19 — GitHub Pages)**: deployed at `https://jeremygideonbareh.github.io/resume-analyser/` (branch `gh-pages`, built from `dist/`). `vite.config.ts` sets `base: '/resume-analyser/'` (Pages subpath — required for assets). `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` are inlined at build time from `.env.local` (if unset, sign-in shows "Sign-in isn't set up yet" and the zero-upload analyser still works untouched). ## Placement Assistant (Core 4) — Wave 5 (plan `.omo/plans/placement-assistant.md`, branch `feat/placement-assistant`)

Turned careerBoT into a student placement assistant. **Exactly 4 modules** per the user's decision (D2); everything else in the original spec is Phase 2 (listed below, NOT built — only explicit "coming in Phase 2" empty states).

### Modules

1. **Student profile** (`Profile` in the signed-in header) — `src/components/ProfileView.tsx`: academic (full name, department select, semester 1–8, CGPA 0–10 step 0.01, backlogs ≥ 0), skills (chip input, comma-separated), certifications, programming languages (fixed common list + free text), links (portfolio/github/linkedin with `http(s)://` validation), target role. Load on mount, upsert on save (`student_profiles`), completeness meter (progress bar + %), inline validation errors, sonner "Profile saved" toast. Signed-out → gate message.
2. **AI placement chatbot** (`Assistant` in the signed-in header) — `src/components/ChatView.tsx` + `api/chat.ts`: conversation UI (user right / assistant left, mono timestamps, Enter to send, loading dots, disabled send in flight), history from `chatbot_messages` (asc), quick-suggestion chips ("Am I eligible for IBM?" / "Improve my resume" / "How should I prepare for interviews?" — last two route to analyser/report via `onNavigate`). **Eligibility is deterministic (D7)**: the server evaluates the profile against each company's criteria with pure rules, then hands the facts to the LLM as context; the reply renders a compact Eligibility card (company, Eligible/Not eligible badge, ✔ reasons). The LLM never decides eligibility — it only words it. Guards (D11): POST-only 405, ≤ 2 KB 413, per-user rate limit ≥ 2 s → 429 (tracked in `chatbot_messages` last timestamp), 10 s upstream 504, prompt-injection instruction in the system prompt, never logs message/resume text.
3. **Resume-analyzer completion** — `api/grammar.ts` (strict-JSON LLM prompt → `{ issues: [{ message, suggestion, context }] }`, fence-stripped + validated) + `src/components/AiFeedbackSection.tsx` rewrite: grammar issues checklist (context snippet, message, suggestion, "Apply" copies suggestion to clipboard) + AI improvement cards from `improvements[]`/`suggestions[]`. `api/analyze.ts` prompt reworded to bias improvements toward concrete resume edits (contract unchanged — `AiFeedback` shape intact). All gated by `VITE_ENABLE_LLM === 'true'` (existing gate semantics — `/api/grammar` literal folds out of dist when off, grep-verified).
4. **Placement dashboard** — `src/components/dashboard.tsx` + `src/lib/dashboard-data.ts`: **Placement Readiness** KPI (D8 formula `clamp(round(0.5×resumeScore + 0.3×skillCoverage + 0.2×profileCompleteness), 0, 100)` + band from `scoreBand`), **Eligible companies** card (list with ✔ reasons via `src/lib/eligibility.ts`), **Applications** card (count by status + list + minimal add form: company select from seeded companies or free-text name + status select; upsert into `applications`), **Skill progress** bar (`profileSkills.length / 10`), **Phase-2 placeholders** (Interview / Aptitude / Coding cards, `DashboardEmpty` styling, "Coming in Phase 2"). Placement queries use `Promise.allSettled` → missing tables degrade to empty instead of erroring the view.

## Credential-storage policy (all credentials stored locally)

- **Single source of truth:** `.env.local` (gitignored). Contains every secret: `SUPABASE_PAT`/`SUPABASE_ACCESS_TOKEN`, `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_BASE_URL`, `LLM_TIMEOUT_MS`, `VERCEL_TOKEN`, `VERCEL_OIDC_TOKEN`, `VITE_ENABLE_LLM`.
- **GH token:** stored in the OS Git Credential Manager (Windows), never in the repo.
- **Vercel env store** is a runtime MIRROR only — refreshed from `.env.local` via `npm run secrets:sync` before deploying. Serverless functions read from Vercel at runtime (`LLM_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, …); the source of truth for those values is `.env.local`.
- **Enforcement:** `npm run secrets:check` (also run automatically by the pre-commit hook) fails if any credential is missing from `.env.local` or if a real token value (sbp_/gsk_/vcp_/gho_/JWT/service_role) appears in any tracked file or anywhere in git history.
- **Manual deploy with local creds:** `npx vercel --prod --token "$(node -e "console.log(require('fs').readFileSync('.env.local','utf8').match(/VERCEL_TOKEN=(.+)/)[1])")"` — keeps the token on disk, not pasted into chat.
